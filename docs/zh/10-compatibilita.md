# 兼容性与测试

🌐 [Italiano](../10-compatibilita.md) · [English](../en/10-compatibilita.md) · **中文**

> ⚠️ 本页为机器翻译草稿，正式发布前需母语者校对。

本页说明哪些内容已对照真实程序验证过，哪些没有。它不是一份承诺清单。

**测试版本：** subfinder v2.17.0，官方 release 二进制文件，macOS arm64。

## 已验证的内容

1. **配置中的标志确实存在。** 每个配置用到的标志都已与测试版本 `subfinder -h` 的输出逐一比对：没有未知标志。
2. **被禁标志确实存在。** 被禁清单同样与真实的帮助信息做了比对，以免禁止臆造的名称，同时查找遗漏的危险标志。确实找到了一些，并已补充。
3. **真实运行可用。** 用真实二进制文件执行 `subfinder-cli lancia ... --esegui`，并用 `rapporto` 读取结果。
4. **stdin 已关闭。** 有些工具也会从 stdin 读取目标，而这些目标不经过作用域检查。程序会关闭子进程的 stdin；有一个使用假可执行文件的测试证明了这一点，用真实二进制文件的测试见下文。
5. **结果格式。** 解析器读取的是真实输出，保存在 `tests/fixtures/` 中（见其中的 README）。
6. **二进制文件正确。** `doctor` 和 `--esegui` 会检查 PATH 中的可执行文件确实是 subfinder，而不是同名的其他程序。已分别用真实二进制文件（通过）和假文件（拒绝，退出码 5）测试。
7. **Python 与安装。** 测试在 macOS 上的 Python 3.11.18 和 3.13、Linux 上的 3.12.3 中通过。在全新 venv 中用 `pip install .` 干净安装成功，命令也已加入 PATH。
8. **类型。** `mypy --strict` 在 `src/` 中未发现错误。这不能证明代码正确，但能额外检查参数和返回值实际可能是什么；它已纳入 CI，因此不会在没有测试报错的情况下悄悄失效。
9. **测试的实际覆盖范围。** 用 `coverage` 测量覆盖率：低于 85% 时 CI 失败，实际数值更高。一个从未实际测量过的数字毫无意义。



## 未验证的内容

已在 `example.org` 上测试 `base` 和 `sorgenti` 配置。其余配置（`completo`、`ricorsivo`、`prudente`）仅验证了标志。需要 API 密钥的数据源未经测试。

## 如果你使用其他版本

输出格式和标志会随版本变化。如果 `subfinder-cli doctor` 显示的版本不同，测试是无从知晓的。在信任它之前，请运行 `make check`，更重要的是，在你自己的靶机上做一次试运行。如果你发现某个能绕过作用域的标志不在被禁清单中，那就是一个漏洞：见 [SECURITY.md](../../SECURITY.md)。
